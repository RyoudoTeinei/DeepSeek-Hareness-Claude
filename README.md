# DeepSeek Hareness Claude

在 DeepSeek Harness（DSH）的原生聊天界面和终端里使用 VPS 上的 Claude Code。默认由服务器上的 Claude 思考和管理对话，通过 SSH 调用本机 Claude Code，直接读写本机项目、运行命令。

正常说「修改 README」「运行测试」即可，接入时插件会配置好执行位置。

## 工作方式

| 部分 | 负责的工作 |
| --- | --- |
| VPS 上的 Claude Code | 对话、推理、原生权限流程，以及 Agent、定时任务、WebSearch、WebFetch 等服务器侧功能。 |
| DSH 插件 | 原生聊天与终端接入、SSH 转发、会话绑定，以及本机返回文本中的 IP 和时区处理。 |
| 本机 Claude Code | 以 `claude mcp serve` 运行，提供文件读写、编辑、搜索、工作树、Bash、PowerShell 等执行能力。 |

本机执行工具目录随本机 Claude Code 更新，工具参数和执行行为沿用其原生实现。服务器侧功能继续由 VPS 会话处理。

- **代码位置**。默认直接操作 DSH 选中的本机文件夹。VPS 的 `~/projects/<远程目录名>` 用于启动和归档 Claude 会话。
- **权限确认**。由服务器 Claude Code 当前权限模式处理，原生提示显示在 DSH 右侧终端。
- **联网位置**。WebSearch、WebFetch 从服务器侧发起。本机 Bash、PowerShell 中的 `curl`、安装依赖等命令使用本机网络和代理配置。
- **切换执行位置**。取消「在本机工作区执行」并重新接入，会切换到服务器工作区并恢复当前对话。

## 安装与首次接入

本机需要 Windows 版 DSH、Claude Code、Node.js、Git 和 OpenSSH。文件同步还需要 Python 3.10 或以上版本。Linux VPS 需要 Claude Code、Python 3.10 或以上版本、Git 和 tmux。

1. 在 VPS 上完成 Claude Code 登录，并确认本机能够通过 SSH 密钥登录服务器。
2. 在 DSH 插件管理器添加此仓库并启用。插件默认使用桌面 `desktop` profile，其他 profile 需要调整 `client.js` 中的插件路径。
3. 在 DSH 打开本地项目。将鼠标移到工作区名称上，点插头图标。
4. 填写 SSH 主机和远程目录名。主机可以是 `user@host` 或已有 SSH 别名，使用默认 SSH 配置时私钥路径留空。
5. 默认勾选「在本机工作区执行」，点击「接入 Claude」。在左侧选择 Claude Code 模型后即可正常聊天。

SSH 通道会自动建立，服务器需要允许 Unix 套接字转发。本机工具服务只监听本机回环地址。连接地址和密钥由用户自己的工作区或 SSH 配置提供。

## 独立会话与恢复

每条 DSH 新聊天在首次接入时分配独立的 Claude 对话 ID 和 tmux 会话。同一条聊天的左侧消息、右侧终端和图片上传绑定到同一个 Claude 会话。

- 同一项目的多条聊天拥有独立上下文，共享同一个项目文件夹。
- 重新接入会回到仍在运行的 Claude 进程。进程已退出时，恢复该聊天最后使用的对话。
- 原生 `/clear`、`/resume` 切换后，通过会话开始事件记录实际对话 ID，供下次恢复使用。
- 左侧停止按钮发送 Claude 原生中断，并等待当前轮次停止。后台任务可通过原生任务工具管理。
- SSH 中断后重新接入；若 MCP 仍显示断开，在 `/mcp` 中重连本机服务。

旧版本已经建立的共享会话保留原绑定。升级后新建的聊天使用独立会话。

## IP 与时区处理

处理发生在本机工具结果通过 SSH 发回 VPS 之前。插件移除识别到的明文 IP 和时区值，直接返回处理后的内容。

- 保留路径字段、识别出的路径和版本号。
- 保留 JSON 字段名、数组、值类型、原有格式和大整数，避免字段被改名或合并。
- IP 和时区命中值直接移除，替换结果为空文本。
- 工具发现、参数和权限流程沿用原生接口。

例如，下面的返回值：

```json
{"ip":"192.0.2.10","version":"1.2.3.4","path":"C:\\project\\UTC\\readme.md"}
```

会处理为：

```json
{"ip":"","version":"1.2.3.4","path":"C:\\project\\UTC\\readme.md"}
```

识别范围是文本中的地址、时区名称及偏移等格式。无时区标识的文件修改时间会保留，图片和二进制内容沿用原生传输。SSH 连接来源和命令的联网出口由实际网络配置决定。Claude Code 自己附加的账户、日期等上下文由 Claude Code 管理。

## 文件同步

本机执行模式可以直接读写代码，文件同步是可选功能。需要 VPS 上也保留项目副本时，可以使用双向自动同步。

- **首次开启**。远端目录不存在时确认创建；两端已有文件时先查看差异。
- **差异处理**。支持 Git 风格的彩色差异，逐项或批量选择保留本地或服务器版本。写入前核对文件版本，并备份被替换的内容。
- **规则与备份**。可调整后缀预设、忽略规则、大小限制和备份策略，同时读取项目的 `.gitignore`、相关 `.gitattributes` 属性和 `.editorconfig`。
- **状态保存**。两端项目的 `.dsh-sync/` 保存基线、日志和备份，并从同步中排除。DSH 重启时恢复已开启且未暂停的同步任务。
- **兼容功能**。手动 Git 推送、快进拉取和 Mutagen 同步收在「旧版同步」中。同一项目切换到自动同步前，先暂停旧版任务。

默认单文件上限为代码和文档 10 MiB、图片和 PDF 25 MiB、其他文件 100 MiB。模型权重、视频和压缩包默认关闭，可自行调整。

自动同步处理工作目录文件，两端 Git 历史各自维护。空目录、重命名识别、符号链接复制和完整 ACL 同步目前尚未支持。

## 其他功能

- 工作区名称旁显示同步状态，点击状态标签可打开同步界面。
- 支持剪贴板图片上传到远端并插入对应 Claude 会话。
- 左下角显示 Claude Code 状态栏提供的 5 小时和每周额度、重置时间及更新时间。
- 模型选择器支持具体 Claude 型号，以及跟随右侧终端当前模型。

## 开发验证

```bash
npm test
```

覆盖 JavaScript 语法、同步设置、回复读取、Git 推送保护、PowerShell 启动参数、独立会话绑定、返回文本处理和会话恢复逻辑。

安装本机 Claude Code 后，可以运行原生工具集成测试：

```bash
npm run test:native
```

集成测试使用临时项目验证原生读写、搜索、Bash、PowerShell、后台输出和本机转发连接的关闭。真实 VPS 验证还覆盖普通指令操作本机、聊天隔离、执行位置切换、停止前台命令，以及 `/clear`、`/resume` 后恢复。
