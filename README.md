# DeepSeek Hareness Claude

**本分支：`feature/cloud-cc-local-vm`，当前快照 `0.4.0-vm.8`。** 这是一条独立的本地虚拟机执行路线，保留 Windows 版 DeepSeek Harness 的原生聊天与真实服务器终端。

| 代码线 | 项目文件和命令在哪里执行 |
| --- | --- |
| `main` 的 0.6.0 路线 | Windows 本机 Claude Code 的 `claude mcp serve` |
| 本分支 | 独立 Linux 虚拟机中的未登录 CC MCP 服务，通过受限共享访问本机项目 |

两条路线独立维护，版本号分别演进。本分支保留云端 CC 的 Agent、Skill 和会话上下文；Windows 上的日常 CC、Claude Desktop 不作为执行器使用。

## 在 DSH 安装和更新 VM 版

在 Windows DSH 的「插件 → 添加插件」中，粘贴下面一整行，选择安装并启用。已在 DSH `0.2.2-rc.5` 的独立 profile 实装验证。

```text
https://github.com/RyoudoTeinei/DeepSeek-Hareness-Claude.git#feature/cloud-cc-local-vm
```

地址中 `#` 后的内容选择 Git 分支。复制浏览器地址栏的 `/tree/feature/cloud-cc-local-vm` 会被这个版本的安装器拒绝。只填仓库根地址会安装默认分支 `main`。两个版本使用同一个包名 `dsh-plugin-remote-claude`，一个 DSH profile 只选择其中一条路线。

**以后更新。** 从上述分支地址安装后，完成当前任务、从托盘退出 DSH，再在 PowerShell 运行下面这条命令。它按已保存的分支刷新插件，然后重新打开 DSH 即可。已在独立 profile 验证它能获取分支的新提交，即使两次提交的包版本号相同。

```powershell
dsh plugin --profile desktop up dsh-plugin-remote-claude
```

普通重启沿用 `pnpm-lock.yaml` 锁定的提交。如果只想用图形界面，可在插件管理器移除该插件，再用同一个带 `#` 的地址安装并启用。在 desktop profile 的 `package.json` 中，`dsh-plugin-remote-claude` 的来源应以 `#feature/cloud-cc-local-vm` 结尾。若需要固定一个可复现的快照，可以把分支名换成该分支上特定提交的完整 40 位 SHA。

**从以前的本地安装迁移。** 如果来源是 `link:...`，DSH 当前加载的是那个本地目录。想改由 GitHub 提供版本，可在完成当前任务、从托盘退出 DSH 后运行一次下列 PowerShell 命令，再打开 DSH 核对插件已启用。这条命令已在临时 profile 验证能把同名包从 `link:` 切换到 VM 分支。

```powershell
dsh plugin --profile desktop add 'https://github.com/RyoudoTeinei/DeepSeek-Hareness-Claude.git#feature/cloud-cc-local-vm'
```

**首次使用。** 新电脑还需按[虚拟机准备说明](docs/vm-setup.md)配置独立执行环境。已有执行器保留原注册和磁盘即可。在本地项目的新聊天中打开「Claude 工作台」，配置 SSH 主机与远程工作区，点击「接入 Claude」，在左侧选择 `Claude Code · 远程工作区`。

这是已在专用 Windows / QEMU / Linux VPS 环境验证的预览分支，尚未提供通用一键安装。仓库包含插件、测试及 VM 准备脚本，不包含虚拟磁盘、CC/QEMU 二进制、密钥、登录配置或个人会话数据。

## 左侧工作区与会话（0.4.0-vm.8）

已添加的 Claude 工作区采用暖橙色文件夹，右侧的「Claude ›」可打开工作台。聊天行按 DSH 记录的模型选择显示 Claude 或 DeepSeek 标签，切换模型后随之更新。一个项目内可同时有两种聊天；尚无可识别模型记录的行保留默认样式。

## 接入、恢复与关机（0.4.0-vm.7）

首次接入填写 SSH 主机，远程目录、模型和私钥在「更多设置」中。面板一时读不到配置时可点击「重新读取连接配置」。已绑定聊天点击「重连当前会话」会沿用原绑定。每个聊天同一时间只启动一条连接，同时接入的调用者分别收到同一连接的结果。

电源操作使用进程退出即释放的系统文件锁。虚拟机启动并验证身份后才清除手动关机标志。关机确认逐条列出项目、聊天标题（无标题时显示短 ID）和已知执行状态；确认期间新增连接或有聊天开始前台任务时，界面会再次展示受影响的会话。

附件在写入项目之前统一检查，每轮最多 10 个，每个文件或图片最多 100 MiB。会话与电源状态合并读取，同一聊天的可见面板共享刷新；空闲时降低刷新频率，隐藏后暂停。

## 虚拟机电源（0.4.0-vm.6）

工作台新增「执行虚拟机」电源区，可查看状态并启动或关闭整台虚拟机。打开 DSH 只检查状态，不再预先启动；点击「启动虚拟机」或「接入 Claude / 继续会话」时才启动。手动关闭状态保存在该虚拟机自己的控制目录，后台恢复、重开 DSH 和旧启动脚本都不能自行唤醒。

有会话连接时，关机操作先列出受影响的项目。确认「断开全部并关闭」才会停止这些本机执行进程；确认后若连接列表已变化，会重新要求核对。其他 DSH 后台持有的连接不能被本后台直接关闭。关机前校验 QEMU UUID，发送正常关机请求后等待实际停止，不会把请求已发送误报成已关机，也不会强制断电。

关机保留本机项目文件、虚拟磁盘中的依赖与文件、DSH 聊天以及服务器上的 Claude 会话记录。未完成的命令及其内存状态会结束，之后需重新执行。磁盘仍占存储空间，CPU 与虚拟机运行内存则释放。

关闭聊天面板不关机；Windows 版窗口右上角「×」会隐藏到托盘。真正从托盘退出 DSH 时，插件清理本机连接并尝试正常关闭专用虚拟机；如果其他后台还在使用，则保留虚拟机。再次打开 DSH 保持按需启动。

## 界面更新（0.4.0-vm.5）

工作台沿用 DSH 的浅色/深色主题变量和字体，优先显示项目、连接状态与进入 Claude 的主操作。已绑定会话的连接设置默认折叠，首次连接时展开；只读字段仍可选择复制。开始页使用 DSH 原生入口卡片，侧栏保留宿主原有的文字和选中样式。

最近活动将内部工具名称显示为「执行命令」「读取文件」「编辑文件」等动作，并按调用 ID 合并开始和完成记录；旧日志也可兼容显示。新记录附带操作描述或文件路径及耗时。完整错误收在详情中，权限确认保留可检查的操作内容。终端工具栏、额度弹层和旧版文件同步面板使用一致的中性色、圆角与焦点样式。

## 旧服务器模式（历史兼容说明）

下列同步功能保留给旧服务器执行会话；本分支的新聊天使用上面的虚拟机流程，不需要先 Git 推送项目才能工作。

1. 本地安装 Node.js、Git 和 Windows OpenSSH。远端需能通过 SSH 登录，并已安装 Git、tmux、Python 3 和 Claude Code。
2. 在 DSH 插件管理器添加此 GitHub 仓库，启用插件。在左侧点击「＋ 添加 Claude 工作区」，选择本地文件夹并填写 SSH 主机、远程项目名。默认使用桌面 profile 的 ~/.dsh/profiles/desktop；其他 profile 需调整 client.js 中的插件路径。
3. 点击「接入 Claude」或「服务器 Terminal」。同一个 SSH 用户、主机和工作区可重新接回仍在运行的 tmux 会话。重新接入会取得交互控制权并断开同一会话的旧终端连接，远端进程和对话继续保留；终端启用鼠标支持。
4. 在「文件同步」中筛选、全选或勾选文件，填写说明并确认推送。Git 将当前分支已有提交和本次所选文件提交直接推到远端同名分支。远端已有的未跟踪输出文件不会阻止无关文件的推送；已跟踪文件的未提交改动和会被覆盖的同名文件仍会阻止推送。拉取使用快进合并。面板显示本地提交阶段、已用时间和 Git 上传进度。
5. 若需要自动回传未提交的文件，请从 [Mutagen 官方发布页](https://github.com/mutagen-io/mutagen/releases/tag/v0.18.1) 安装 Windows 版本，将 mutagen.exe 加入 PATH，保留配套的 mutagen-agents.tar.gz，重启 DSH。随后按项目启用「自动回传服务器文件」。使用系统 SSH 配置或 SSH 别名。远程文件创建、修改和删除会传播到本地，冲突保留供处理，关闭面板后同步继续。首次启用前请核对两端路径。
6. 工作台支持将剪贴板图片经 SSH 上传至自己的服务器，插入远程路径后手动确认发送。

## 原生终端、聊天与附件（0.3.2-native.3）

在 Claude 工作台勾选「原生 Claude 终端 · 附件自动上传与成果回传」，点击「接入 Claude」。右侧是通过 SSH 连接的真实 Claude Code TUI，可直接输入、滚动、使用 `/model` 和处理权限提示。左侧消息进入同一进程、同一会话。运行中切换模型请在右侧使用 `/model`；工作台模型选项只在启动新进程时生效。

原生终端顶部提供鼠标模式、复制选中、上下翻页和回到底部。默认「鼠标选字」让拖选保留在本机 xterm，可按 Ctrl+C 或点「复制选中」复制；有选区时 Ctrl+C 不发送中断，没有选区时仍可中断任务。切换「鼠标操作 CC」后点击交由远端 CC 处理，仍可按住 Shift 拖选本机文字。滚轮通过插件明确编码并发送到当前终端，不改变其他终端或服务器全局 tmux 配置。PgUp / PgDn 和 Ctrl+End 也是 CC 全屏渲染器的原生滚动快捷键。

失败或停止后的旧用户消息可能仍保留在 DSH 上下文中。新消息只发送最后一条明确标记为用户手动输入的消息，保留稳定请求标识供去重；不会自动重放旧任务，也不会将时区或运行环境消息一起发送。

本机只运行 Node.js/PowerShell 插件代码，不安装或启动本机 Claude。每个 DSH 聊天使用独立的 `dsh-native-<scope>` tmux 会话，文件位于 `~/.local/state/dsh-remote/structured-v1/`。从之前的结构化预览版切换时，恢复该聊天已经保存的 Claude 会话 ID。旧任务仍在执行时拒绝启动另一进程；原生终端已经运行时可重新接入，不重启 CC。不会重启其他 tmux 会话或修改全局 Claude 配置。

在左侧添加文件或图片并发送，插件从 DSH 附件存储读取原始内容，校验哈希后上传至远端项目的 `.dsh-attachments/`。每轮最多 10 个附件，单文件最大 100 MiB。上传失败时本轮不会开始执行。右侧有草稿、未处理的提示或任务正在运行时，左侧发送会提示先处理，不会清空右侧输入框。

左侧读取真实 Claude 会话记录中的正文和工具进度，不再从终端可见区域截取答案。正文按 CC 写入的内容块到达，不保证逐字同步；不会将思考正文或整段工具原始输出混进答案。权限确认在右侧原生界面完成。左侧停止按钮请求中断本轮，保留 CC 进程；重复的已完成请求重放结果，不再次执行。右侧直接发起的回合保存在同一 Claude 历史中，下次左侧消息能够继续该上下文；当前版本不会在左侧空闲时主动创建一条 DSH 消息来镜像右侧回合。

左侧发起任务生成成果时，Claude 调用 `publish_artifact` 发布项目内文件。插件下载不可变快照并校验大小及 SHA-256，保存到本机插件数据目录，左侧显示回传提示，工作台提供保存路径与「打开成果」按钮。历史成果在当前会话中保留最近 50 项。普通 Office 文档、PDF、图片和文本可用系统应用打开，其他文件类型仅保存。右侧单独发起任务的文件可使用已有文件同步功能回传。

用户正文和主动添加的附件参与远端任务，自动注入的本机环境上下文与消息源时区等元数据不会进入提示词。服务器使用其已有登录和执行环境，SSH 服务端仍能看到连接来源。「服务器 Terminal」按钮打开项目 Shell；「接入 Claude」打开上述原生 CC 会话。旧的日志运行窗口不再作为默认界面或工作台入口。

## 本地虚拟机执行器

新聊天统一使用本地虚拟机，不再提供执行模式勾选框。模型登录和推理在服务器；独立 QEMU/WHPX Debian 虚拟机内运行固定版本 Claude Code 2.1.322 的 `claude mcp serve`，不登录、不提供模型或网络工具。Windows 日常 CC 与 Claude Desktop 的安装和配置不被使用。虚拟机只共享选定项目目录。云端保留 Agent、Skill、规划、任务和网络工具，项目读写与 Shell 仅通过虚拟机 MCP 执行。历史服务器模式聊天只按原绑定恢复，不会因工作区设置变化而改变执行位置。

使用时新建 DSH 聊天，核对本地文件夹后直接点「接入 Claude」。连接信息和执行模式固定在聊天上；重开界面自动读取，不从工作区偏好推断。云端 CC 进程还在时重新附着到同一进程；已退出时使用保存的会话 ID 执行 `--resume`。左侧继续发消息时也会恢复已断开的 VM 连接。需要确认的工具操作仍在右侧原生终端处理。共享文件直接写回本机，不需要 Git 推送；聊天附件存入项目的 `.dsh-attachments/`。

升级后需要重启 DSH。vm.2 的已建立虚拟机会话继续沿用原终端名称和会话 ID；新建虚拟机会话使用独立的 `dsh-vm-native-<scope>` 名称和独立会话 ID 种子，避免与普通服务器模式撞名。控制器检查后台版本和默认模式策略，防止新文件与旧后台混用。vm.1 旧执行器需新建聊天升级。

DSH 按需启动执行虚拟机。关闭工作台或终端标签不关闭后台桥或虚拟机。点「断开连接」只断开本聊天的文件桥并清理本聊天的执行进程；其他聊天继续运行。「关闭虚拟机」作用于整台执行环境，详见上面的电源说明。没有配置 Windows 开机自启动。

同一台虚拟机支持多个项目和聊天同时连接。每个聊天使用独立挂载点、CC MCP 进程、HOME/配置/临时目录、任务记录和连接锁。Bubblewrap 0.12.0 在虚拟机内为每个 CC 建立独立的文件系统、PID、用户、IPC 和网络命名空间，只挂载本聊天的项目及私有状态；不允许看到其他项目或终止其他聊天的进程。Bubblewrap 安装在客机用户目录，未修改 Windows 或服务器的容器配置。隔离不可用时拒绝启动，不回退到未隔离执行。

不同项目的文件相互隔离。同一个本机项目的多个聊天共享原文件夹，但云端会话上下文与执行进程独立；修改会立即体现在该目录，同时修改同一文件仍需协调。没有自动创建工作副本或合并。多会话共享虚拟机 CPU 和内存，实际并发规模受可用资源限制。

终端接入先执行带 20 秒期限的非交互准备检查，再直接通过 SSH 附着到已验证的 tmux 会话，不再在交互 SSH 内嵌套 Python 捕获准备输出。显式设置 `TERM=xterm-256color`，兼容 Windows 终端的默认类型，并显示连接阶段。重连保留同一 Claude 进程或恢复原会话 ID。

标题适配器识别 DSH 标题插件专用的 JSON 消息封装，使用真实用户正文生成简短标题，不再因来源过滤而统一变成「Claude 远程任务」。打开旧聊天或继续发送消息时，自动生成的旧占位标题会经 DSH 标题服务重新生成；用户手动命名不改动。

执行器通过 `%LOCALAPPDATA%/DSH-Remote-Claude/vm-executor.json` 注册，包含专用客机 SSH 指纹、密钥路径、实例 ID、隔离网络状态、启动脚本以及宿主 Python 路径。Python 需有 Paramiko。云端 v2 桥只使用 Python 标准库，部署于 `~/.local/state/dsh-remote/vm-native-v2`，不覆盖旧版桥或全局 Claude/MCP 配置。该注册文件不能放进共享项目。

实现文件：`vm-manager.mjs` 管理生命周期；`vm-runtime.mjs` 建立出站 SSH 桥；`vm-sftp.py` 只导出授权目录并拒绝路径穿越、链接和根目录替换；`vm-relay.py` 与 `vm-mcp.py` 转发原生工具协议；`vm-native.mjs` 持有一个长驻客机 CC；`vm-native.py` 校验客机身份，以独立 HOME/配置/临时目录和环境白名单启动 CC，禁用非必要流量及自动更新。发现凭据或账号元数据会拒绝启动。用户目录、Claude/SSH 等个人配置和虚拟机控制文件不能作为共享根目录。

执行器暴露该固定版本实际提供的 Read、Write、Edit、NotebookEdit、Bash 和 TaskStop；原生 Read 支持分页及图片等内容块，Edit 保留读后修改检查。该版本未提供单独的 Glob/Grep，通过 VM Bash 的命令搜索。客机目前提供 Python 与基础 Linux 工具，公网网络关闭，项目依赖仍需另外准备。前台命令上限 120 秒，长任务使用 `run_in_background`，通过 VM Read 读取 `backgroundOutputPath`。原生 MCP TaskStop 存在任务登记差异，因此桥接层用 `vm-job.py` 为 Bash 创建独立进程组，记录 PID 与启动时间，并仍通过原生 Bash 执行停止。只接受本连接返回的任务 ID。断开时结束该 CC 及其子进程，保留虚拟机。

云端的 `vm-project` 原生子代理可使用虚拟机 MCP 工具；普通内置子代理或自定义 Agent 的工具白名单未必包含 MCP，应使用该代理或显式配置。Skill 在云端加载，定义中的服务器脚本路径不会自动映射为 VM 路径；需要在 VM 准备脚本和依赖，并让 Skill 使用 VM MCP 工具执行。云端 Agent 任务与 VM Bash 后台任务分别管理。工具没有 Windows Shell、浏览器或桌面操作能力。断线或执行结果不确定时不会自动换到宿主/服务器执行，也不会盲目重放写入请求。

Bash 的每次调用从共享项目目录开始，命令内的 `cd` 和 `export` 不延续到下一次调用；使用绝对路径或在同一命令里切换目录。MCP 取消通知和左侧停止会终止对应的前台命令。已经明确启动的后台任务通过 VM TaskStop 停止，断开整个执行器时统一清理。

## 原桌面工具模式（历史兼容说明）

已有桌面模式绑定会继续按原配置恢复。相关的 `desktop-remote.py` 及请求处理代码保留用于兼容；新聊天不再提供这个模式的勾选入口，而是统一使用虚拟机执行环境。

Claude 会获得 `desktop_request_artifact` 和 `desktop_request_status` 两个 MCP 工具。它可以请求下载项目中的成果，或者下载后用本机应用打开 PDF、普通 Office 文档、图片和文本。回到工作台的「本机操作」面板选择允许或拒绝。`completed` 表示文件已保存并且系统接受了打开请求，不表示文件内容或应用显示已经验证。最大文件大小为 100 MiB，请求 15 分钟后过期。关闭连接标签后暂停处理，重新连接后可以继续查看请求。

文件通过 SSH 传回，大小与 SHA-256 校验通过后发布到本机 `%LOCALAPPDATA%/DSH-Remote-Claude/desktop/<scope>/received/<request-id>/`，面板显示实际保存位置。每个请求使用独立目录，避免覆盖已有成果。项目之外的路径、符号链接和直接打开可执行文件的请求会被拒绝。下载操作仅保存文件，打开操作会启动本机默认应用。

远端工具只收到请求 ID 和处理状态。插件不把本机绝对路径或本机异常详情加入工具结果，也不自动把消息源中的时区、语言等元数据加入 Claude 提示词。SSH 桌面连接关闭 `SendEnv` 自动环境变量转发。用户主动发送的内容、文档本身以及 SSH 连接来源仍具有各自的信息边界。

首版网页预览采用远端生成截图后回传图片的方式。任意本机命令执行和本机浏览器自动化尚未开放。直接打开文档使用系统关联应用，文档内嵌的外部资源行为由该应用控制。
