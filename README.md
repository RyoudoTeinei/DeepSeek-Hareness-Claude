# DeepSeek Hareness Claude

Windows 版 DeepSeek Harness 的远程 Claude Code 工作区插件。在本地选择项目，通过 SSH 连接自己的 Linux 服务器，在 DSH 内使用 Claude 原生终端、服务器 Shell 和文件同步面板。

## 使用

1. 本地安装 Node.js、Git 和 Windows OpenSSH。远端需能通过 SSH 登录，并已安装 Git、tmux、Python 3 和 Claude Code。
2. 在 DSH 插件管理器添加此 GitHub 仓库，启用插件。在左侧点击「＋ 添加 Claude 工作区」，选择本地文件夹并填写 SSH 主机、远程项目名。默认使用桌面 profile 的 ~/.dsh/profiles/desktop；其他 profile 需调整 client.js 中的插件路径。
3. 点击「接入 Claude」或「服务器 Terminal」。同一个 SSH 用户、主机和工作区可重新接回仍在运行的 tmux 会话。重新接入会取得交互控制权并断开同一会话的旧终端连接，远端进程和对话继续保留；终端启用鼠标支持。
4. 在「文件同步」中筛选、全选或勾选文件，填写说明并确认推送。Git 将当前分支已有提交和本次所选文件提交直接推到远端同名分支。远端已有的未跟踪输出文件不会阻止无关文件的推送；已跟踪文件的未提交改动和会被覆盖的同名文件仍会阻止推送。拉取使用快进合并。面板显示本地提交阶段、已用时间和 Git 上传进度。
5. 若需要自动回传未提交的文件，请从 [Mutagen 官方发布页](https://github.com/mutagen-io/mutagen/releases/tag/v0.18.1) 安装 Windows 版本，将 mutagen.exe 加入 PATH，保留配套的 mutagen-agents.tar.gz，重启 DSH。随后按项目启用「自动回传服务器文件」。使用系统 SSH 配置或 SSH 别名。远程文件创建、修改和删除会传播到本地，冲突保留供处理，关闭面板后同步继续。首次启用前请核对两端路径。
6. 工作台支持将剪贴板图片经 SSH 上传至自己的服务器，插入远程路径后手动确认发送。

## 结构化聊天与附件

在 Claude 工作台勾选「结构化聊天」，选择远端模型并点击「接入 Claude」。已有工作区需要手动开启一次。连接后直接在左侧 DSH 聊天输入框添加文件或图片并发送，插件通过 DSH 附件存储读取原始内容，校验哈希并上传到远端项目的 `.dsh-attachments/`。每轮最多 10 个附件，单文件最大 100 MiB。上传失败时本轮不会开始执行。

此模式使用服务器 Claude Code 的 `stream-json`，本机只运行 Node.js/PowerShell 插件代码。每个 DSH 聊天拥有独立 Claude 会话 ID，远端服务位于 `~/.local/state/dsh-remote/structured-v1/`，与旧版 tmux 和其他插件部署目录分开。服务器端需要 Python 3.8+ 和支持结构化输入输出的 Claude Code。首次接入此模式创建新会话，随后自动恢复。

文字增量直接显示在左侧，工具开始/完成显示为独立状态块。权限请求优先使用 DSH 审批提示，宿主无法显示时，在工作台「任务与成果」中确认。停止按钮中断当前模式启动的远端进程，已结束的同一请求会重放保存的事件，而不会再次执行任务或再次请求审批。

生成成果时，Claude 调用 `publish_artifact` 发布项目内文件。插件下载不可变快照并校验大小及 SHA-256，保存到本机插件数据目录，左侧显示回传提示，工作台提供保存路径与「打开成果」按钮。历史成果在当前会话中保留最近 50 项。普通 Office 文档、PDF、图片和文本可用系统应用打开，其他文件类型仅保存。打开文档可能加载其中的外部资源，行为由本机应用决定。

用户正文和主动添加的附件参与远端任务，自动注入的本机环境上下文与消息源时区等元数据不会进入该模式的提示词。服务器会使用其已有登录和执行环境，SSH 服务端仍能看到连接来源。结构化聊天与旧终端模式分别维护上下文，服务器 Terminal 是项目 Shell，不会连接同一个 print-mode 进程。

## 原桌面工具模式

工作台勾选「桌面模式」后点击「接入 Claude」，会为当前 DSH 聊天创建独立的远端 Claude 会话，并将 `desktop-remote.py` 安装到服务器的会话状态目录。服务器需要 Python 3.8+、tmux 和支持 `--mcp-config`、`--session-id` 的 Claude Code。桌面模式首次使用从独立会话开始，后续连接恢复该会话。原有模式仍可通过取消勾选后重新接入使用。

Claude 会获得 `desktop_request_artifact` 和 `desktop_request_status` 两个 MCP 工具。它可以请求下载项目中的成果，或者下载后用本机应用打开 PDF、普通 Office 文档、图片和文本。回到工作台的「本机操作」面板选择允许或拒绝。`completed` 表示文件已保存并且系统接受了打开请求，不表示文件内容或应用显示已经验证。最大文件大小为 100 MiB，请求 15 分钟后过期。关闭连接标签后暂停处理，重新连接后可以继续查看请求。

文件通过 SSH 传回，大小与 SHA-256 校验通过后发布到本机 `%LOCALAPPDATA%/DSH-Remote-Claude/desktop/<scope>/received/<request-id>/`，面板显示实际保存位置。每个请求使用独立目录，避免覆盖已有成果。项目之外的路径、符号链接和直接打开可执行文件的请求会被拒绝。下载操作仅保存文件，打开操作会启动本机默认应用。

远端工具只收到请求 ID 和处理状态。插件不把本机绝对路径或本机异常详情加入工具结果，也不自动把消息源中的时区、语言等元数据加入 Claude 提示词。SSH 桌面连接关闭 `SendEnv` 自动环境变量转发。用户主动发送的内容、文档本身以及 SSH 连接来源仍具有各自的信息边界。

首版网页预览采用远端生成截图后回传图片的方式。任意本机命令执行和本机浏览器自动化尚未开放。直接打开文档使用系统关联应用，文档内嵌的外部资源行为由该应用控制。

## 开发验证

本地安装 Node.js、Git 和 Python 3.8 或更新版本后，运行 `npm test`。测试使用标准库和临时 Git 仓库，覆盖多块 Claude 回复的完整读取，以及推送时对服务器文件的保护。
